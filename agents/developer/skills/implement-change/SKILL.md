# 需求实现

输入输出见 [任务协议](../../../../docs/contracts.md)。

1. 核对工作区、基础 SHA、当前分支和已有变更，读取适用仓库指令及相关代码。若工作区不符则停止，不能通过重置清除未知修改。
2. 将验收标准对应到实现和验证方式，按项目约定做范围内的变更。需要改需求或依赖外部系统时交回统筹。
3. 执行与变更相称的检查，记录命令、退出码、结果及限制。依赖安装或测试需要额外能力时返回具体阻塞。
4. 将差异、自检证据、分支和提交 SHA 作为产物保存；GitLab 角色已启用；本地交付不自动推送。远程交付时，仅在本次授权范围内推送分支并交 GitLab 角色管理 MR。
5. 返工时逐项处理评审或 CI 问题，说明修复与验证，新提交必须重新评审。

结果区分实际实现、自检结论和待独立验收事项。不修改主分支、不持有业务系统凭证、不将失败或未运行的检查写成通过。
