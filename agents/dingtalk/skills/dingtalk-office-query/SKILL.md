# 办公查询

按 [工具清单](../../../../config/mcp-catalog.json) 的显式 read 工具执行；不要仅凭名称判断只读。`get_friend_request_list` 会标记申请已读，`get_app` 可能自动创建应用，都不作为只读探测。

## 路由与口径

- 人员：默认当前授权企业。企业通讯录人数优先查询根部门详情的 `memberCount`，注明根部门统计口径；个人好友数量应分页查询好友列表，按稳定人员 ID 去重，不与企业人数相加。根部门 ID 从实际组织上下文确认；已知根部门为 1 时可查询 1。
- 部门成员：需要遍历时按父子部门逐层查询，记录可见范围、去重与分页完成情况，不能将可见子集称为企业总人数。
- 文档/知识库/钉盘：先检索定位对象，再按需读取内容；名称不唯一时返回候选，不猜测写入目标。
- AI 表格：先定位 Base 和表，读取字段定义再查询记录；普通表格先确认工作表及单元格范围，区分两类产品。
- 待办/日历/日志：默认查询当前用户，明确未完成/已完成、角色、时间区间及组织范围。相对日期按 Asia/Shanghai 解析。
- 邮箱：先定位当前用户的邮箱，再按条件查询，统计时明确文件夹、时间和是否包含已删除邮件。
- Teambition 项目/任务：交回统筹，由 Teambition Agent 执行。

## 结果要求

只读请求不自动创建任务、发送邮件、建群或通知。答案返回原请求渠道；通过机器人向钉钉另发一条消息属于单独的写操作。

分页统计必须读完或标为部分结果；空列表表示本次查询未命中，不等于组织不存在数据。`success=false`、嵌套业务错误、权限不足都不能因外层 `isError=false` 而忽略。

输出简短答案、统计口径、时间/来源、完整性及限制。仅保存必要证据，不在公共配置中写入真实人员、手机号、邮箱或成员明细。
