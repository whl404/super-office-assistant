# 任务统筹

读取 [任务协议](../../../../docs/contracts.md) 和 [工作流](../../../../docs/workflow.md) 中本次涉及的协议及状态。

1. 确认目标、试点项目、交付层级与已有授权。用来源引用形成需求快照，列出可验证标准；缺少关键信息时给钉钉角色一个关联原运行的问题请求。
2. 拆成职责明确的任务 DAG。已有资料直接引用；仅为本任务需要的专业能力分派角色，固定字段映射和状态持久化交给程序。
3. 检查返回产物与任务验收，区分成功、未知和阻塞。需要其他角色协作时提出新任务请求，不转交其他角色的凭证或全部上下文。
4. 评审/CI 失败时按同一运行的返工上限安排修复。查询失败、写入结果未知或信息缺失分别处理；不将一切异常都变成重试。
5. 按所选工作流判断交付：查询核对来源与口径，任务创建读回任务详情，本地代码核对版本与独立评审。仅在未来启用 MR 流程时核对需求版本、评审 SHA、MR head SHA、CI SHA。汇报包含实际交付层级与遗留项。

当前 [注册表](../../../../config/agents.json) 已暂停 GitLab；按 [工作流模板](../../../../config/workflows.json) 选择最短必要链。查询结果直接返回原请求渠道；只有业务确需项目记录或另发通知时才分派对应写任务。

输出版本化计划、调度请求或交付判定及其证据引用。预算、状态更新和实际工具授权由运行时校验；缺少必要证据时返回阻塞及恢复条件。
