# 任务执行模式

按任务选择 `human_review`（人工审核）或 `full_auto`（全自动）。未指定时使用工作区默认值；工作区未配置时默认人工审核。规则见 [execution-modes.json](../config/execution-modes.json)。模式适用于任务执行阶段，不把只读监听升级为自动开发授权。

用户已授权的执行型监听默认使用全自动（`authorized_monitor_default_mode`），明确要求人工审核的任务及严格审批动作例外。CPQ 监听已获得该授权并更新定时执行指令；纯只读监听仍不自动获得开发权限。群消息转任务仍须先确认草稿，确认后才进入自动执行。复杂度本身是模式建议，不是已授权全自动任务的额外审批门槛；需求不清或超出授权范围仍需澄清。

| 阶段 | 人工审核 | 全自动 |
| --- | --- | --- |
| 需求整理与方案 | 准备范围、改动点、验收标准后由用户审核 | 在授权范围内自行规划，关键歧义先澄清 |
| 实现、测试、评审 | 方案批准后自动执行 | 自动执行 |
| MR 与合并 | 准备具体差异、验证证据和 MR；合并前用户审核 | 按工作区授权，检查当前 SHA、流水线、冲突、审批和实际合并差异后合并 |
| 转测试 | 合并后按工作区规则自动回写并转交 | 合并后按工作区规则自动回写并转交 |

人工审核的合并检查点优先于工作区自动合并偏好。用户批准绑定方案版本；合并批准绑定具体 MR、源提交和目标分支，提交或范围改变后重新审核。不要只问笼统的“是否继续”。

复杂任务（跨仓库、公共接口或数据模型调整、验收条件不明确、影响面未知）推荐人工审核；明确且局部的修改可选择全自动。不能仅凭代码行数判断复杂度，也不因模型认为简单就自动升级执行权限。全自动中出现范围扩大、关键歧义或达到返工上限时，保存进度并请求用户决策。

两种模式都保留既有边界：群消息建任务需用户对草稿确认；数据库每次变更先展示精确 SQL、环境/数据库/表、条件和预计行数并逐次确认，保持 mysql_dev_write 原生 prompt，DDL 禁用。全自动不代表自动发布生产或任意群消息发送。

当前此配置供统筹指令与本聊天执行使用，尚未由独立调度器加载并强制执行。底层 auto/ai/user 是单个工具的审批模式，与本文件的任务执行模式不同；本配置不解除 mandatory_user_tools 或工具自身审批。生产运行时必须接入模式选择、版本化检查点与可信审核渠道后，才能声称无人值守执行已启用。
