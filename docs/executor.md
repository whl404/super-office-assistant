# 统一工具执行器

## 已实现与尚未接入

[执行器](../agent_runtime/executor.py) 是可运行的异步 Python 组件，负责单次业务工具操作，不包含模型调度。已实现角色/技能/工具核验、精确参数授权、验证器入口、响应错误识别、有限只读重试、调用预算、SQLite 操作记录、目标写锁、取消和写入对账。

本轮使用模拟适配器测试，没有通过 Python 执行器调用真实 MCP。生产 MCP 连接、实时 Schema 校验器、可信授权签发端、资料存储及完整工作流引擎仍需接入。当前 Codex 中已有的 MCP 连接不会自动传给本组件。

现已加入 [三种操作批准模式](approvals.md)。身份与任务授权通过后，还需策略批准；批准不增加权限。等待批准不创建外部操作记录或占用目标锁。

## 运行离线演示

```powershell
python -m agent_runtime.demo
python -m unittest discover -s tests -v
```

演示使用临时数据库和模拟远端：创建已生效但响应丢失→再次请求被阻止→只读对账查到原对象→重复请求返回已确认。模拟创建次数为 1，真实业务调用次数为 0。

## 调用契约

1. 可信控制面创建 `Ledger` 和运行记录，设置发起人、组织、计划版本、截止时间及 `max_calls`。
2. 适配层为明确工具注册 `Binding`：异步调用函数、实际 Schema 验证器、响应分类器。写适配器还必须从真实目标参数推导规范化 `resource_key`；创建对象使用父容器等稳定目标，不使用待生成的对象 ID。
3. 控制面构造不可变 `TaskContext` 和 `Grant`。Grant 绑定用户、组织、运行、任务、计划版本、工具、完整参数摘要、期限及策略版本。写 Grant 的目标键必须与适配器推导结果一致。
4. 调用 `execute`，使用同一业务动作重试期间保持不变的 `logical_key`。批准层绑定具体动作和精确参数，按 auto/ai/user 处理；待审返回 approval_id，批准后才能执行。建议逻辑键包含运行/任务及动作标识，不能每次重试随机生成。维护对账只查询旧操作，不重发写入，使用原有恢复授权机制。
5. `Outcome` 返回状态、错误类别、操作 ID、验证层级及当前内存中的结果。重复确认不缓存原始业务正文，`payload=None`；通过操作记录关联产物，或按适配器安全回读。

`Grant` 不是加密令牌，其可信性来自调用进程的控制面。不能把 HTTP 请求或模型 JSON 直接解析成 Grant，也不能给模型进程提供数据库、授权签发器或任意 Python/Shell 执行权限。生产服务需将控制面与模型输入隔离。

通用分类器检查 MCP `isError`，解析 structuredContent 或单个 JSON 文本块，检查顶层和 result/data 信封中的失败标记，不递归把业务记录的 `success` 字段当成接口错误。供应商使用其他返回结构时必须提供专用分类器；未分类的文本不直接判为成功。

## 异常与重试

| 情况 | 已实现行为 |
| --- | --- |
| 参数、身份、角色或授权不匹配 | 调用前阻止，返回具体类别 |
| 工具未注册 | 返回 `CAPABILITY_UNAVAILABLE`，不根据名称虚构能力 |
| 只读网络故障、可识别服务临时错误 | 默认最多 3 次重试，2/5/15 秒退避并加抖动 |
| 限流 | 同时遵守服务返回的 retryAfter；等待超过任务/授权期限时停止 |
| 权限不足或业务失败 | 只读请求不自动重试；检查业务错误而非仅看外层调用状态 |
| 写调用已发出后超时、失败或返回矛盾 | 保守记为 unknown；不假定失败等于没有副作用 |
| 结果未知的写入 | 保留目标锁；重复动作不重发，其他同目标写入返回 `RESOURCE_BUSY` |
| 同一目标的不同写操作 | 通过组织与规范目标键串行；已明确未执行的锁等待可安全重试 |
| 并发重复动作 | 原子操作键唯一约束，只允许一个执行者 |
| 调用预算或执行期限到达 | 停止后续调用；预算持久化，重启不会归零 |
| 取消或计划版本变化 | 禁止新调用；迟到成功可记录物理事实，但不能推动旧任务交付 |

预算目前按工具调用次数计数，包括每次重试和对账；模型次数与货币费用预算尚未实现。同步 SQLite 操作很短，网络调用必须使用可取消的 async 适配器；该组件不能安全抢占任意同步代码或替代操作系统沙箱。

## 写入对账与恢复

写适配器可注册 `reconcile(operation_id, arguments_digest)`，实现只读查询，并返回 `applied / not_applied / unknown`。适配器需要基于持久关联标记或供应商幂等 ID 查询，不能凭名称相似或暂时查不到就断言未执行；不具备可靠查询能力时保留 unknown。

- `applied`：确认原操作，标记 `readback_verified`，解除目标锁。
- `not_applied`：标记 `VERIFIED_NOT_APPLIED` 并解除锁，不自动重新写入；由控制面决定是否发起下一次明确的动作。
- `unknown`：继续保留未决状态和锁，不切换到 DWS 重发。

对账也消耗运行预算。新对账租约更换 token，旧工作者不能覆盖结果。重启后 pending 仍在有效租约内时阻止重复操作；租约过期只转未知，不自动重放。unknown 在对账完成前一直保留。

取消或换计划后，可新建同用户、同组织的维护运行，用绑定具体 `reconciliation_operation_id` 的新 Grant 调用 `reconcile(..., maintenance=True)`。这只查询旧动作，不重启已取消任务、不发送新写入。维护授权不能跨用户或组织。

## 存储边界

生产数据库建议放在被 Git 忽略的 `.runtime/` 下。保存运行、操作、事件和目标锁；操作记录含首个/当前尝试、参数摘要、策略版本、授权 ID、租约和结果摘要。维护对账事件记录维护运行与授权 ID。

操作审计表不保存参数和业务正文。现有 [调度器](scheduler.md) 在私有 wf_* 表保存冻结业务参数和产物，并按用户/组织控制读取；工具确认与回执可同事务提交。访问令牌和密钥仍不能进入业务资料。尚无生产数据迁移工具。

现已由 Scheduler 接入任务 DAG、Agent/工具循环、输入和批准等待、租约、产物、验收及交付 outbox；真实模型与网络客户端仍需注册，不能据此声称六个 Agent 已在线常驻。
