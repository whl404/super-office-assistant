# 全局角色、项目规则与绑定

## 运行框架兼容性

当前全局角色安装方案面向 Codex，不是通用 harness 安装器。办公角色的职责、开发规范和交接规则可以迁移；模型提供商与运行框架是两层配置，连接 DeepSeek 模型不会自动获得 Codex 的角色发现和调度能力。

| 内容 | 当前实现 | 其他 harness 的接入要求 |
| --- | --- | --- |
| 角色定义 | `config/global-agents/common.md` 与 `roles.json` | 复用规则，转换为目标框架的角色格式 |
| 角色安装 | 写入 `~/.codex/agents/*.toml` | 适配角色目录、字段和加载方式 |
| 配套技能 | 安装到 `~/.codex/skills/` | 确认技能读取机制并调整路径 |
| 项目绑定与状态 | `~/.codex/workspace-monitors/` 下的配置和状态 | 保留按仓库隔离的语义，适配配置路径 |
| 委派、监听与分聊 | 依赖 Codex 会话能力及单独配置的自动化 | 接入目标框架的调度、持久化和聊天能力 |
| 业务工具与批准 | 依赖接收者实际连接的工具和授权 | 配置 MCP 等连接，并保留逐操作审批边界 |

### 给使用 DeepSeek harness 的同事

先确认具体产品或仓库、版本、角色格式、MCP 支持和审批机制，再决定适配范围。目前没有经过验证的 DeepSeek harness 适配器或安装包；不能仅复制 `.codex/agents` 就宣称可用。现有安装器的 `--codex-home` 只改变 Codex 配置位置，不转换运行框架格式。

迁移时不得携带个人令牌、项目人员、授权或运行历史。先验证六个角色能加载、目标仓库规则与绑定能正确读取，再验证工具发现及只读查询。数据库修改仍需展示精确 SQL、环境、表、条件和预计行数，并获得本人对该次操作的明确确认；写工具保留原生逐次审批，DDL 保持禁用。目标框架无法执行这些约束时，不开放数据库写入。

## Codex 安装与工作区绑定

源码位于 config/global-agents/common.md 和 roles.json。运行 `python scripts/install_global_agents.py` 安装六个个人角色到用户目录 `.codex/agents/`，更新全局 AGENTS.md 的带标记路由段；修改前备份，不改变模型、MCP、审批配置或监听开关。

角色包含统筹、开发、评审、Teambition、GitLab、钉钉。全局角色不硬编码项目ID、成员和GitLab实例；遵守父会话权限及委派限制。项目角色注册表 config/agents.json 仍用于本仓库自己的运行时，不等同于 Codex 全局角色发现机制。

执行时按目标仓库绝对路径匹配用户目录 `.codex/workspace-monitors/*/config.json`，读取目标仓库适用的 AGENTS.md，再读取项目 state.json。执行模式与前后端开发范围独立。无绑定不推断群聊、收件人或外部项目授权。

新增工作区时创建独立绑定（workspace.path/repository、Teambition项目、群、人员、执行和交接政策），建立独立 state.json；不要复制旧任务ID或消息游标。任务基线首次完整查询后建立，不把旧任务当新任务。监听需要独立创建或启用自动化。

CPQ 已有绑定继续使用；仓库根目录 AGENTS.md 保存代码与分支规则。个人交接技能沿用现有安装。CPQ 心跳保持暂停；安装或普通会话不得启动监听。

验证层级：TOML解析、六个角色名称/规则、JSON绑定和技能文件存在性可本地检查；当前聊天不能仅凭文件写入证明客户端已加载新角色。需在重新加载后的会话核验实际可用角色。角色规则不是程序级拦截，也不启动常驻后台进程。
