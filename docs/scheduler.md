# 持久化调度器与完整任务闭环

## 已实现

[Scheduler](../agent_runtime/scheduler.py) 将角色配置、任务 DAG、Agent 回调、工具执行器、三档批准、产物、验收和交付事件接成一个可恢复流程。工作流仍以已审核模板为边界，模型不能任意增加角色权限或改写执行图。

```text
接收事件并去重 → 保存输入与计划 → 按依赖分派 Agent
→ Agent 请求工具 / 请求补充 / 提交产物
→ 任务授权 + 自动/AI/用户批准 → 工具执行与回执
→ Agent 根据回执继续 → 验收证据 + 业务验收器
→ syncing 与 outbox 同事务保存 → 原渠道确认交付 → delivered
```

核心循环是实际代码，真实模型、MCP 网络客户端及钉钉渠道尚未接入。模型回调目前由离线演示提供，不能据此声称已在线自动办公。

## 运行演示

```powershell
python -m agent_runtime.workflow_demo
python -m unittest discover -s tests -v
```

演示包含：只读查询完整交付，以及写操作等待用户批准→关闭数据库模拟重启→恢复批准记录→执行一次→验收→确认交付。所有 Agent、工具及用户审核均为模拟，真实业务调用为 0。

## 接入点

1. 创建共用 Ledger、Executor、Scheduler，数据库放在被 Git 忽略的 `.runtime/`。
2. 为业务工具注册真实 Binding，提供当前参数 Schema 验证、返回值分类及可靠回读策略。
3. `register_agent` 绑定独立异步模型/工作进程适配器。Job 包含角色指令、候选工具、任务上下文、当前输入、直接依赖产物和本步骤历史回执。
4. Agent 仅返回 ToolRequest、Complete 或 NeedInput。控制面检查类型、白名单、动作 ID、内容大小等；模型回调不直接取得业务工具或数据库。
5. `grant_issuer` 从可信用户/资源策略签发精确 Grant，不能把 inputs 中的授权字符串当作权限。该函数不可修改被冻结参数，同一动作恢复期间保持授权 ID 稳定；授权过期或需扩大范围时重新审核。
6. `register_validator` 注册独立可信业务验收器。除结构检查外，应核对验收标准、目标对象及事实，不依据模型“完成”文字放行。
7. 认证渠道调用 submit / provide_inputs / user_decide 等 API；actor 必须来自验证过的身份与组织。

本模块不选择模型供应商，也不把 Codex 的 OAuth 凭证复制到工作区。生产网络接入、用户认证、模型预算/费用计量和本地代码沙箱仍属于部署适配工作。

## 分派、等待与自动唤醒

`submit` 冻结模板和输入，建立持久运行与步骤；source + organization + event_id 去重，重复载荷复用原运行，载荷或身份冲突拒绝。

`drive` 只执行依赖成功的步骤；工具请求先持久化动作及稳定逻辑键，再执行。Complete 必须生成实际产物。需要信息时保存缺失字段和问题，provide_inputs 仅允许填补当前请求字段，并校验 input_version。

批准等待保存 approval_id，既不占用模型进程，也不占目标写锁。`serve(stop_event)` 提供后台轮询：新任务、补充信息和已批准动作会自动继续，不需要用户手动重跑 drive。后台首版串行轮询运行；多个驱动可共享数据库，通过租约争抢步骤，尚未实现专用分布式队列。

拒绝、撤销、过期、权限不足、预算耗尽和未知写入等进入 blocked，不反复询问或无限重试。解决阻塞后由可信控制面调用 resume；未知写入恢复只执行已注册的查询对账，不重复写入。缺少回读能力时继续阻塞。

## 中断恢复和证据

- 步骤租约有唯一 token，长操作通过心跳续租；中断后过期租约可重新取得，旧 token 不能提交结果。
- 工具确认与私有回执在同一 SQLite savepoint 内提交；回执存储失败则回滚确认，写入进入 unknown。
- 在“工具成功、调度步骤尚未更新”处崩溃，恢复时读取原回执，重新检查任务授权及批准，不重复调用写工具。
- 等待批准、输入版本、历史动作、产物及调用预算都保留，重启不会清零预算。
- 工作流 template 的 requires_tool_effect 要求指定步骤拥有本版本、本轮次的真实工具回执；没有工具证据的假成功不能交付。
- 必要证据通过后才调用业务验收器；未注册验收器直接阻塞，不默认通过。

产物读取检查 run 所属用户和组织，依赖传递仅包含当前版本已成功的直接依赖；每轮返工的旧产物保留，但不自动混入新结果。

## 返工、改需求和取消

验收器可返回有限返工请求。无外部写入的流程会重置目标步骤及依赖它的后续步骤，增加 generation，重新查询并验收；计数达到上限停止。

存在已确认、待确认或结果未知的外部写入时，不自动重放整条链：返回 WRITE_REWORK_REQUIRES_NEW_PLAN。控制面需在新任务中显式关联已有对象，决定更新、补偿或对账，不能重复创建。

revise 支持尚无外部写入的计划修订：递增 plan_version，冻结新输入，作废旧步骤/交付事件，保留原始产物和已消耗预算。已有写入时拒绝盲目重建计划，原对象继续保留。

cancel 停止新调度并取消本进程中的等待；远端已生效操作不能撤回，未知结果仍保留在执行器账本。取消、期限和版本检查会阻止迟到结果推进流程。停止 serve 是停工作者，不等于用户取消业务任务；未完成运行可重新恢复。

## 验收与交付 outbox

验收通过后，同一事务写入最终产物引用和唯一 outbox 事件，运行进入 syncing。渠道按稳定 event_id 取得结果，确认后调用 acknowledge_delivery，才进入 delivered。重复确认不会产生新交付事件。

outbox 不是自动发送邮件或消息的许可。若渠道需要通过钉钉发送消息，应走消息工具的用户批准和操作对账；源 API 的结果返回则可直接消费本地交付事件。跨系统 exactly-once 仍取决于渠道幂等/回执能力，不能通过重复发送来代替确认。

## 数据和边界

操作审计表保持仅存摘要；调度器的 wf_* 私有表会保存业务输入、冻结动作参数和产物正文，供审批续跑与恢复。数据库不进入 Git，服务进程和认证 API 控制读写；没有内置磁盘加密、保留期清理或生产迁移工具。

存储限制为单个 JSON 1 MiB，拒绝明显的凭证字段；这不是全面的敏感数据识别。适配器必须先过滤凭证，不把 token 或密钥嵌入资料正文。数据库故障或无权限等基础设施异常仍需进程监管和备份恢复。

已有的六个模板都可注册适配器，但只有离线已注册的场景具备演示模型、假工具和验收器。未注册的模型/验收器/授权签发器会明确阻塞；GitLab 模板已启用，生产适配器仍需注册。本地代码模板不提供真实隔离工作进程，不能把模型返回的代码说明视为已经执行。
